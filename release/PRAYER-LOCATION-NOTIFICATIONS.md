# Prayer location and local notification revision — 2026-10-07

Implementation checkpoint, not device acceptance or App Store readiness. Apple/Firebase credential handoff remains deferred by the user. No new distribution build number is assigned here.

## Changes and files

- `ios/Athar/PrayerLocationController.swift`: explicit opt-in When In Use permission, kilometer accuracy, movement updates while foreground active, geocoder-derived country/time zone, fresh/valid-fix checks, timeout/error UI, last complete saved location retained on failure. No Always permission, location background mode, heading or closed-app travel tracking. A new country/time zone must resolve before coordinates replace the old location; offline failure does not mix a new fix with the old country's calculation profile.
- `ios/Athar/Store.swift`: validates and preserves `location.*` locations across restarts; optional timestamp migrates old JSON. Existing bookmarks and other data remain. Unknown legacy manually stored cities retain their existing migration behavior. Manual city selection exits location mode and clears the in-memory GPS comparison cache, so re-enabling location resolves the device again. Incomplete geocoder responses keep the previous valid location with an error message; stale failure callbacks are ignored after deactivation.
- `ios/NoorWidgetShared/PrayerEngine.swift` and `Services.swift`: one library (Adhan Swift pinned 1.5.0), automatic country defaults, location-local calendar and Ramadan interval, latitude-dependent night approximation. Old manual method fields decode but no longer control live app/widget calculation. UAE/Qatar/Kuwait/Egypt/Pakistan/Bangladesh/Afghanistan/Singapore/Malaysia/Indonesia/Turkey/US/Canada/UK have region presets; other countries use Muslim World League. This version-1 policy is an app default, **not official timetable verification for every city**. Late afternoon calculation in Pakistan/Bangladesh/Afghanistan is a regional default. Turkey uses the library's approximate preset. Polar dates may yield no calculable times; never fabricate notifications.
- `PrayerNotificationPlan.swift`, `Services.swift`: deterministic prayer/day IDs, future-only requests, suppression of IDs still present in Notification Center as delivered, per-prayer toggles, optional advance, serialized reconciliation, owned-request cleanup, legacy cleanup, checks after async adds, 42 maximum prayer requests from a ten-day calculation horizon. Reserving room for 7 salawat and 14 Friday requests keeps the app's three plans under a conservative 64-request budget. Existing unrelated requests further reduce capacity. A full queue is reported. These are changing astronomical dates, not fixed repeating prayer times.
- `PrayerAlertSound.swift`, `prayer-adhan.caf`: bundled 24-second mono PCM CAF, validates duration before selecting custom UNNotificationSound, default fallback, silent and system options. No long playback, silent-audio loop or critical-alert entitlement.
- `SalawatNotificationPlan.swift`: independent opt-in, 2/4/6-hour or once-daily cadence, silent daily calendar slots between 09:00 and 21:00, varied Arabic text, maximum 7 requests; disabled by default. These daily reminders follow the device local clock (floating hour/minute components), so travel does not leave quiet hours pinned to the previous city; prayer triggers retain the saved location time zone. Friday salawat requests are suppressed while general salawat is enabled.
- `PrayerView.swift`, `PrayerNotificationSettings.swift`: calculation picker/card removed, concise permission/fallback UI, location opt-in/update, each prayer/sound/cadence preferences. `FeatureViews.swift` erases location/salawat preferences during existing explicit data deletion.
- `AtharApp.swift`, `PrayerBackgroundRefresh.swift`, `Info.plist`: reconcile at opening/foreground, stored-location change, significant time/day change; request optional six-hour background refresh and use the last persisted location in its SwiftUI app-refresh handler. iOS decides when/if refresh runs. Already scheduled local requests do not require the app to stay running. **No guarantee of indefinite prayer coverage without reopening, exact midnight execution, background travel detection, force-quit replenishment, or bypassing Focus/Silent.** Device reboot delivery has not been tested.
- Legal source JSON and generated offline/support pages now explain actual location/geocoder/scheduling behavior. Generated website files are not proof of public deployment. The content audit now checks prayer-specific foreground location permission independently of forbidden compass/Qibla code.
